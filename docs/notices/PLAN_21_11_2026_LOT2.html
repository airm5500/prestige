Cohérence et bilan

  • Totaux : pour chaque cas du détail, total CA TTC, marge et quantité de l'API = sommes des lignes de l'ancienne requête ; totaux des périmés (stock, valeur d'achat, valeur de vente) = sommes de la base.
  • Ordre : chaque liste est triée sur la clé demandée (marge, CA, quantité) ; pages 1 et 2 = début de la liste entière, dans le même ordre.
  • Bilan : tout est en lecture seule, sauf le test de la prévision qui modifie deux ventes de la base de test (date de clôture, annulation) et les remet à l'identique, vérifié en base.
  • Les trois chemins de lecture des tiers payants sont exercés par le test, et le chemin d'origine reste en secours si un index manquait.

Correction ajoutée : code interne d'un nouveau client

Défaut confirmé (ancien, hors lot) : le code interne d'un nouveau client était tiré de l'heure (minute, seconde, millième, coupé à six chiffres). Sur une base de plusieurs dizaines de milliers de clients, il retombait souvent sur un code déjà pris : « Créer client standard » et « Créer » refusaient la création (« Le code interne existe déjà ») ; la création depuis la vente, elle, enregistrait un second client portant le même code. La copie de test compte déjà 26 817 clients pour 25 790 codes différents, soit environ un millier de codes en double, créés par ce chemin.
CorrectionTestAvant → après
Code tiré au hasard entre 100000 et 999999 et redemandé tant qu'il est pris (util.CodeInterneClient). Appliqué aux créations de client de la gestion des clients (standard, « Créer ») et de la vente. Un code saisi à la main et déjà pris reste refusé. client/test-code-interne-client-2111 : tous les codes que l'ancien calcul peut donner pendant cinq minutes sont occupés, puis deux clients standards, un « Créer » assuré, un client créé depuis la vente, un code saisi déjà pris.
